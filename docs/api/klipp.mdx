The camera director: it runs every [virtual camera](/api/virtual-camera), picks the winner, blends between shots, and puts the result on your camera.

`Klipp` works with any renderer: put its `shot` on your camera after `update`. Integrations write it for you, like `KlippThree` for three.js and `<Klipp>` for React Three Fiber.

## Members

| Member | Description |
| ------ | ----------- |
| `addCamera(name, options)` | Creates a [virtual camera](/api/virtual-camera) and adds it. |
| `add(camera)`, `remove(camera)` | Adds or removes a camera you created. Adding moves it from any other klipp. |
| `update(dt)` | Runs one frame. Returns `true` while something is still moving or the shot changed. |
| `shot` | The current shot, see below. |
| `setSize(width, height)` | The viewport size in pixels, for pieces that frame by screen position. |
| `setDefaultBlend(blend)`, `setCustomBlends(blends)` | Change the blends at any time. |
| `registerUpdate(fn)` | Runs `fn` every frame before the cameras, for input. Returns a function that stops it. |
| `whileOnScreen(camera, start, { waitForBlend })` | Calls `start` while `camera` is on screen, and the function it returns once it leaves, for example to connect input. With `waitForBlend` (the default), only once the blend into it has finished. Returns a function that stops. |
| `mode` | `'enabled'`, `'standby'` or `'disabled'`. See below. |
| `activeCameraId`, `isActive(name)` | The winner, the camera the shot is heading to. |
| `liveCameraId`, `isLive(name)` | The camera fully on screen, once the blend into it has finished. |
| `isBlending` | Whether a blend is in progress. |

klipp is also an event target, see [Events](/api/events).

## `mode`

| Mode | Cameras update | Camera is written |
| ---- | -------------- | ----------------- |
| `'enabled'` | yes | yes |
| `'standby'` | yes | no |
| `'disabled'` | no | no |

Use `'standby'` to hand the camera to something else for a while (an editor, a photo mode). klipp keeps its cameras updated in the background, so they're ready the moment you switch back.

## The shot

`shot` is a `CameraState`:

| Field | Description |
| ----- | ----------- |
| `position`, `quaternion` | Where the camera is and how it's turned: `[x, y, z]` and `[x, y, z, w]`. |
| `fov`, `near`, `far` | Lens settings, `fov` in degrees. |
| `viewOffset` | Shifts the view without moving the camera, as a fraction of half the viewport. `[0, 0]` is centered. |

`shot` changes only once the first camera goes live, and stays put in `'standby'`. To react only when it changes, override `write`, see [Building on the core](/getting-started/building-on-the-core#your-own-integration).

`Klipp` works with any renderer. Call `update` every frame and put `shot` on your camera:

```ts
import { Klipp, BlendCurves } from '@kvvasuu/klipp';

const klipp = new Klipp({ defaultBlend: { curve: BlendCurves.easeInOut, time: 1 } });
klipp.setSize(canvas.width, canvas.height);
klipp.addCamera('main', { priority: 10 });

function frame(dt: number) {
  if (klipp.update(dt)) {
    engine.camera.setTransform(klipp.shot.position, klipp.shot.quaternion);
    engine.camera.setFov(klipp.shot.fov);
    engine.render();
  }
}
```

New cameras start from `initialCameraState`, an option of `Klipp`. Pass your camera's starting pose there.

`KlippThree` is `Klipp` driving a three.js camera. `update` writes the shot to it:

```ts
import { BlendCurves } from '@kvvasuu/klipp';
import { KlippThree } from '@kvvasuu/klipp/three';

const klipp = new KlippThree(camera, { defaultBlend: { curve: BlendCurves.easeInOut, time: 1 } });
klipp.setSize(innerWidth, innerHeight);
klipp.addCamera('main', { priority: 10 });

renderer.setAnimationLoop(() => {
  klipp.update(dt);
  renderer.render(scene, camera);
});
```

New cameras start from the camera's `fov`, `near`, `far`, position and rotation at the time `KlippThree` is created. Lens changes need a `PerspectiveCamera`. `camera.aspect` stays yours to update on resize, next to `setSize`.

`<Klipp>` creates a `KlippThree` on the React Three Fiber camera and runs it every frame. It has to be inside `<Canvas>`.

```tsx
import { BlendCurves } from '@kvvasuu/klipp';
import { Klipp } from '@kvvasuu/klipp/react';

<Canvas>
  <Klipp defaultBlend={{ curve: BlendCurves.easeInOut, time: 1 }}>
    <VirtualCamera name="main" priority={10}>...</VirtualCamera>
  </Klipp>
</Canvas>
```

| Prop | Description | Default |
| ---- | ----------- | ------- |
| `defaultBlend` | How to blend between cameras. See [Blending](/blending/introduction). | `{ curve: BlendCurves.easeInOut, time: 2 }` |
| `customBlends` | Blends for specific camera pairs. See [Custom blends](/blending/introduction#custom-blends). | `[]` |
| `camera` | The camera to drive. | the r3f default camera |
| `mode` | `'enabled'`, `'standby'` or `'disabled'`. See [`mode`](#mode). | `'enabled'` |

Virtual cameras start from the real camera's `fov`, `near`, `far`, position and rotation, so whatever you set on `<Canvas camera={...}>` is the starting point. It keeps the viewport size in sync for you.

[`useKlipp()`](/api/hooks#useklipp) gives you the `KlippThree` behind `<Klipp>`, with the members above, and [`<Klipp.Events>`](/api/events) listens to every transition.
