Camera code in a React Three Fiber scene usually ends up as a pile of `useFrame` callbacks doing manual
lerps, look-ats, and ad-hoc shake. `klipp` replaces that with declarative, composable pieces instead.

> [!WARNING]
> Early-stage, experimental - API may change in future releases.

```bash
npm install @kvvasuu/klipp
```

## Body & Aim - independent by design

A camera's **position** (`Body`) and **rotation** (`Aim`) are computed by two completely separate pieces -
follow one target with one damping curve while looking at a totally different one.

```tsx
import { Klipp, VirtualCamera, Body, Aim } from '@kvvasuu/klipp/react';

function Scene({ playerRef }) {
  return (
    <Klipp>
      <VirtualCamera name="follow-cam" priority={10}>
        <Body.Follow target={playerRef} offset={[0, 3, 8]} damping={0.5} />
        <Aim.HardLookAt target={playerRef} />
      </VirtualCamera>
    </Klipp>
  );
}
```

## Multi-camera blending

Mount a second `<VirtualCamera>` with a higher `priority` and Klipp blends into it automatically - no
manual state machine required, including mid-blend interruption (the outgoing camera stays live until its
own blend actually finishes).

```tsx
<Klipp>
  <VirtualCamera name="follow-cam" priority={10} active={true}>
    <Body.Follow target={playerRef} offset={[0, 3, 8]} damping={0.5} />
    <Aim.HardLookAt target={playerRef} />
  </VirtualCamera>
  <VirtualCamera name="cutscene-cam" active={isCutscene} priority={20}>
    <Body.HardLockToTarget target={cutsceneCamPosition} />
    <Aim.HardLookAt target={playerRef} />
  </VirtualCamera>
</Klipp>
```

The base `@kvvasuu/klipp` entry is the framework-agnostic engine (no React/R3F required) - the React
bindings (`<Klipp>`, `<VirtualCamera>`, `Body`, `Aim`, `Noise`, `Extension`, ...) live under
`@kvvasuu/klipp/react`. `CameraControls` (opt-in, pulls in `camera-controls`) is a separate subpath:
`@kvvasuu/klipp/react/camera-controls`.
