<Intro>
  Stop hand-rolling `useFrame` callbacks full of lerps and look-ats. Declare the shot you want, mount as many cameras as your scene needs, and let **klipp** arbitrate priority and blend between them for you.
</Intro>

```bash
npm install @kvvasuu/klipp
```

> [!WARNING]
> Early-stage, experimental - API may change in future releases.

## Why not just useFrame?

Because a real camera rig is never one lerp. It's a tracking target, a look-at target that's a *different* object, a dead zone so the shot doesn't jitter on every twitch, a hard limit so it never loses the subject entirely, a smooth handoff to a cutscene camera and back, screen shake that fades out instead of cutting - and all of that logic ends up tangled in one callback, hard to reuse across scenes. klipp splits it into small, independent, composable pieces instead - swap one out, reuse another across scenes, and reason about (or unit-test) each piece in isolation.

## Do I lose manual control?

No. `CameraControls` is a first-class citizen, not an afterthought - a `<VirtualCamera>` can be a fully user-driven orbit rig (drag, scroll, pan) that still participates in priority arbitration and blends smoothly into/out of other cameras. And every Body/Aim/Noise/Extension exposes a `ref` to its underlying class for imperative access whenever a declarative prop isn't enough.

## Does it cost performance?

No allocations on the hot path. Every per-frame function (`update`, blending, damping) reuses scratch objects instead of allocating - safe to run every frame, on any number of cameras, without generating garbage.

## What does it look like?

```tsx
import { Klipp, VirtualCamera, Body, Aim } from '@kvvasuu/klipp/react';

function Scene({ playerRef, isCutscene, cutsceneCamPosition }) {
  return (
    <Klipp>
      <VirtualCamera name="follow-cam" priority={10}>
        <Body.Follow target={playerRef} offset={[0, 3, 8]} damping={0.5} />
        <Aim.HardLookAt target={playerRef} />
      </VirtualCamera>
      <VirtualCamera name="cutscene-cam" active={isCutscene} priority={20}>
        <Body.HardLockToTarget target={cutsceneCamPosition} />
        <Aim.HardLookAt target={playerRef} />
      </VirtualCamera>
    </Klipp>
  );
}
```

Mount a second `<VirtualCamera>` with a higher `priority` and klipp blends into it automatically - no manual state machine required, including mid-blend interruption (the outgoing camera stays live until its own blend actually finishes).
