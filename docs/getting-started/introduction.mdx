<Intro>
  Describe the shots you want. **klipp** picks the right one and smoothly blends between them.
</Intro>

```bash
npm install @kvvasuu/klipp
```

> [!WARNING]
> Early-stage and experimental. The API may still change.

> [!TIP]
> See it in action on the [examples site](https://kvvasuu.github.io/klipp/examples/).

## Why klipp?

Cameras are a core part of 3D, yet most projects end up rebuilding the same pieces: an offset that follows the player, damping so it doesn't jitter, a dead zone, a cutscene camera and a smooth way back. Written by hand, all of that ends up tangled in one update loop.

Engines like Unity and Unreal solved this years ago with virtual cameras. klipp brings that model to the web: each shot is described on its own, the one with the highest priority is on screen, and switching between shots is a blend instead of a jump.

## One system, any renderer

The core of klipp is a complete camera system: virtual cameras, priority, blending, framing, shake and input. It knows nothing about renderers or frameworks, so it runs anywhere. Integrations are thin layers on top of it:

| Entry point | For |
| ----------- | --- |
| `@kvvasuu/klipp` | The core. Use it with any renderer or engine, or build your own integration on it. |
| `@kvvasuu/klipp/react` | React Three Fiber components. |
| `@kvvasuu/klipp/three` | three.js classes, the layer the React components are built on. |
| `@kvvasuu/klipp/dom` | Mouse, touch and wheel input, and debug overlays. |

Under its classes, the core is plain data and functions on [`math`](https://github.com/pmndrs/math). They are there for when you want full control, for example from an ECS.

These docs show every piece with the core first, then as a React Three Fiber component.

## What it looks like

A follow camera and a cutscene camera, written to your own camera:

```ts
import { vec3 } from 'math';
import {
  KlippCore,
  FollowBodyCore,
  HardLockToTargetBodyCore,
  HardLookAtAimCore,
  createTargetPose,
} from '@kvvasuu/klipp';

const klipp = new KlippCore();
const player = createTargetPose(); // keep player.position up to date
const spot = createTargetPose();
vec3.set(spot.position, 10, 2, 0);

const follow = klipp.addCamera('follow', { priority: 10 });
follow.body = new FollowBodyCore(player, { offset: [0, 3, 8], damping: 0.5 });
follow.aim = new HardLookAtAimCore(player);

const cutscene = klipp.addCamera('cutscene', { priority: 20, active: false });
cutscene.body = new HardLockToTargetBodyCore(spot);
cutscene.aim = new HardLookAtAimCore(player);

// every frame
klipp.update(dt);
engineCamera.setPosition(klipp.shot.position);
engineCamera.setRotation(klipp.shot.quaternion);
```

`cutscene.active = true` blends over to the cutscene camera.

The same with React Three Fiber, where `active={isCutscene}` does the switch:

```tsx
import { Klipp, VirtualCamera, Body, Aim } from '@kvvasuu/klipp/react';

<Klipp>
  <VirtualCamera name="follow" priority={10}>
    <Body.Follow target={playerRef} offset={[0, 3, 8]} damping={0.5} />
    <Aim.HardLookAt target={playerRef} />
  </VirtualCamera>

  <VirtualCamera name="cutscene" priority={20} active={isCutscene}>
    <Body.HardLockToTarget target={[10, 2, 0]} />
    <Aim.HardLookAt target={playerRef} />
  </VirtualCamera>
</Klipp>
```
