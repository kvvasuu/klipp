title: On-demand rendering
description: Render only while the camera is moving.

`klipp.update` returns `true` while anything is still moving (a blend, damping catching up, a shake), or the shot changed this frame. Render only then, and skip frames while the camera has settled.

Keep calling `update` every frame, even while nothing renders. It notices on its own when a target moves or a setting changes. React Three Fiber's `frameloop="demand"` is different: it stops calling frames altogether, so it needs a nudge, see its tab.

klipp works with `<Canvas frameloop="demand">`. It keeps requesting frames on its own while anything is still moving.

Once the camera has settled, nothing renders until something asks for a frame. Mounting a camera, changing its `active` or `priority`, and changing `Lens` props do that for you. For anything else, call `invalidate()` yourself, for example after:

- changing a Body or Aim prop, like a new `target` or `offset`,
- moving a target imperatively, for example `target.position.set(...)` in a click handler,
- firing an impulse with `impulseField.generate()`,
- changing a component's fields through its `ref`.

```tsx
const invalidate = useThree((state) => state.invalidate);

function onClick() {
  targetRef.current.position.set(0, 0, 5);
  invalidate();
}
```

Outside a component, import `invalidate` from `@react-three/fiber` directly.
