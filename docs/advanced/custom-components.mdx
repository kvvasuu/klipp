A piece is any object with an `update` function that runs every frame. Add your own to a camera and it runs alongside the built-in ones:

```ts
camera.body = { update };        // replaces any other Body
camera.aim = { update };         // replaces any other Aim
camera.addExtension({ update }); // stacks
camera.addNoise({ update });     // stacks
```

`addExtension` and `addNoise` return a function that removes the piece. For a Body or Aim, `setBody` and `setAim` do the same, and warn if the camera already has one.

A class with an `update` field works just as well as an object.

## The update function

```ts
(out: CameraState, dt: number, justActivated: boolean) => boolean | void
```

- `out` is the camera's state. Change it in place.
- `dt` is the frame time in seconds.
- `justActivated` is `true` on the camera's first frame, and again when it turns back on. Reset any smoothing here so the camera starts from the right place.
- Return `true` while your piece is still moving, so [on-demand rendering](/advanced/on-demand-rendering) keeps going.

## Example: drift toward the pointer

An Extension that turns the shot slightly toward the pointer, on top of any Body and Aim. It's plain core code, so it works in every layer. `pointer` is `{ x, y }` from `-1` to `1`:

```ts title="pointerDrift.ts"
import { quat, type Euler, type Quat } from 'math';
import { Damper, type CameraPiece } from '@kvvasuu/klipp';

const euler: Euler = [0, 0, 0, 'xyz'];
const rotation: Quat = [0, 0, 0, 1];

export function pointerDrift(pointer: { x: number; y: number }, strength = 0.1, damping = 0.4): CameraPiece {
  const yawDamper = new Damper();
  const pitchDamper = new Damper();
  let yaw = 0;
  let pitch = 0;

  return {
    update: (out, dt, justActivated) => {
      if (justActivated) {
        yawDamper.reset();
        pitchDamper.reset();
      }

      const targetYaw = -pointer.x * strength;
      const targetPitch = pointer.y * strength;
      yaw = yawDamper.update(yaw, targetYaw, damping, dt);
      pitch = pitchDamper.update(pitch, targetPitch, damping, dt);

      euler[0] = pitch;
      euler[1] = yaw;
      quat.multiply(out.quaternion, out.quaternion, quat.fromEuler(rotation, euler));
      return yaw !== targetYaw || pitch !== targetPitch;
    },
  };
}

```

> [!TIP]
> Avoid creating objects inside the update function. Allocate scratch objects once, like `euler` and `rotation` above.

## `CameraState`

| Field | Type | Description |
| ----- | ---- | ----------- |
| `position` | `Vec3` | Camera position. |
| `quaternion` | `Quat` | Camera rotation. |
| `fov`, `near`, `far` | `number` | Lens settings. |
| `viewOffset` | `[number, number]` | Shifts the view without moving the camera. `[0, 0]` is centered. |
| `target`, `hasTarget` | `Vec3`, `boolean` | The point the Body follows, if any. Used by [blend hints](/blending/introduction#blend-hints). |
| `lookAtTarget`, `hasLookAtTarget` | `Vec3`, `boolean` | The point the Aim looks at, if any. |
| `referenceUp` | `Vec3` | Which way is up for Aims. Defaults to `[0, 1, 0]`. |

Vectors are plain arrays (`[x, y, z]`, quaternions `[x, y, z, w]`) from [`math`](https://github.com/pmndrs/math), which klipp depends on. Use its `vec3` and `quat` functions to work with them, or copy to three.js with `vector.fromArray(out.position)`.

## Helpers

These let your pieces behave like the built-in ones. From `@kvvasuu/klipp`:

| Helper | What it does |
| ------ | ------------ |
| `Damper` | Smooths a number with a `damping` value. Call `reset()` to snap on the next update. |
| `damp`, `dampVector3`, `dampQuaternion` | The same as functions over state you keep yourself (`createDamperState()`, ...). |

From `@kvvasuu/klipp/three`:

| Helper | What it does |
| ------ | ------------ |
| `Vector3Damper`, `QuaternionDamper` | `Damper` for a three.js `Vector3` or `Quaternion`. |
| `readTargetPose(out, target, null, withRotation)` | Reads the world position, and optionally rotation, of any [target](/getting-started/core-concepts#targets) into a `TargetPose`. Returns `false` if there isn't one. |
| `resolveTargetPosition(out, target)`, `resolveTargetRotation(out, target)` | The same into a three.js `Vector3` or `Quaternion`. |
| `resolveVector3(out, value)` | Turns `[x, y, z]`, a number or a `Vector3` into a `Vector3`. |

Get the camera with [`useVirtualCamera()`](/api/hooks#usevirtualcamera) and add the piece in `useEffect`: the returned function is its cleanup. r3f's `state.pointer` already has the right shape:

```tsx title="PointerDrift.tsx"
import { useEffect } from 'react';
import { useThree } from '@react-three/fiber';
import { useVirtualCamera } from '@kvvasuu/klipp/react';

export function PointerDrift({ strength = 0.1, damping = 0.4 }) {
  const camera = useVirtualCamera();
  const pointer = useThree((state) => state.pointer);

  useEffect(() => camera.addExtension(pointerDrift(pointer, strength, damping)), [camera, pointer, strength, damping]);

  return null;
}

<VirtualCamera name="menu" priority={10}>

  <Aim.HardLookAt target={[0, 1, 0]} />
  <PointerDrift />
</VirtualCamera>;
```
