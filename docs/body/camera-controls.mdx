A user-controlled orbit camera, built on [`camera-controls`](https://github.com/yomotsu/camera-controls). It still takes part in priority and blending like any other camera. Unlike other Bodies, it controls both position and rotation, so don't add an Aim next to it.

`camera-controls` is a three.js library, so this Body exists for three.js and React Three Fiber only, with no core form.

```bash
npm install camera-controls
```

With a `target`, the camera orbits around it and follows it when it moves. Without one, it's free: orbit, pan and zoom anywhere.

> [!NOTE]
> Use `initialPosition` to set the starting point. The camera's `initialState` has no effect on `CameraControls`.

## Settings

| Setting | Description | Default |
| ------- | ----------- | ------- |
| `target` | What to orbit around. See [Targets](/getting-started/core-concepts#targets). Omit for free controls. | |
| `initialPosition` | Where the camera starts. | |
| `enableTransition` | Animate the internal `camera-controls` calls. | `false` |
| `impl` | A custom `CameraControls` subclass to use instead. | |
| `waitForBlend` | React only. Ignore input until the blend into this camera has finished. | `true` |
| `makeDefault` | React only. Set as r3f's `state.controls` while it accepts input. | `false` |
| `regress` | React only. Lower render quality while moving (`performance.regress()`). | `false` |

`controls` is the `camera-controls` instance, for its own options like `minDistance` or `dollySpeed`, and methods like `rotateTo` or `setLookAt`.

## Usage

```ts
import { CameraControlsBody } from '@kvvasuu/klipp/three/camera-controls';

const body = new CameraControlsBody(ball);
body.controls.minDistance = 2;
klipp.addCamera('orbit', { priority: 10 }).body = body;

body.controls.connect(renderer.domElement);
```

Connect the controls while their camera is on screen and `disconnect()` them otherwise, so several orbit cameras don't fight over the mouse.

  </TabsContent>
  <TabsContent value="r3f">

```tsx
import { CameraControls } from '@kvvasuu/klipp/react/camera-controls';

<VirtualCamera name="orbit" priority={10}>
  <CameraControls target={ballRef} minDistance={2} />
</VirtualCamera>
```

Any option of a `camera-controls` instance can be passed as a prop, and its events too: `onControlStart`, `onControl`, `onControlEnd`, `onTransitionStart`, `onUpdate`, `onWake`, `onRest` and `onSleep`.

Input only works while this camera is on screen, so you can mount several orbit cameras without them fighting over the mouse.

`ref` gives you the `CameraControlsBody`.
