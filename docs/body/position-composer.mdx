Moves the camera, without rotating it, so the target stays at `screenPosition` and `cameraDistance` away. With a `deadZone` the target can move freely inside it before the camera reacts.

It's made for cameras that keep a fixed rotation, like top-down or side-scrolling games, so it's usually used without an Aim. The rotation then comes from the camera's [`initialState`](/api/virtual-camera#initialstate).

The zones react to the target's edge, not just its center, so its size matters. `klipp.setSize` keeps the screen proportions in sync with your viewport.

## Settings

| Setting | Description | Default |
| ------- | ----------- | ------- |
| `target` | What to frame. See [Targets](/getting-started/core-concepts#targets). | |
| `cameraDistance` | Distance from the camera to the target, along the view direction. | `10` |
| `screenPosition` | Where the target should be on screen. `[0, 0]` is the center, `±1` the edges. | `[0, 0]` |
| `deadZone` | Area around `screenPosition` where the target can move without the camera reacting. Same units as `screenPosition`. | `[0, 0]` |
| `hardLimit` | Area the target can never leave, even while `damping` is catching up. `[0, 0]` turns it off. | `[0, 0]` |
| `depthDeadZone` | How far the target can move toward or away from the camera before it reacts, in world units. | `0` |
| `damping` | Seconds to catch up once the target leaves the dead zone. See [Damping](/getting-started/core-concepts#damping). | `0` |
| `maxSpeed` | Maximum catch-up speed, in units per second. | `Infinity` |
| `lookaheadTime` | Seconds to look ahead of a moving target. See below. | `0` |
| `lookaheadSmoothing` | Seconds used to smooth the target's measured speed for lookahead. | `1` |
| `lookaheadIgnoreY` | Only look ahead horizontally, handy for jumping characters. | `false` |
| `radius` | three.js and React. The target's radius. On the core, set the target's `extent`. | |
| `size` | three.js and React. The target's box size, used instead of `radius`. | measured for meshes |
| `debug` | React only. Draws the zones on screen. See [Debugging](/debugging/introduction). | `false` |

## Lookahead

With `lookaheadTime`, the camera frames where the target is going to be instead of where it is, so fast targets get room in front of them.

## Combining with an Aim

Avoid Aims that recenter the target every frame, like `HardLookAt`: they cancel out the dead zone and `screenPosition`. Use one of these instead:

- no Aim, for a fixed rotation,
- [`RotateWithFollowTarget`](/aim/rotate-with-follow-target),
- [`RotationComposer`](/aim/rotation-composer) with the same `screenPosition`, and a non-zero `deadZone` on both.

```ts
import { PositionComposerBody } from '@kvvasuu/klipp';

player.extent.radius = 0.5; // so the zones react to its edge
camera.body = new PositionComposerBody(player, { cameraDistance: 12, deadZone: [0.3, 0.2], damping: 0.3 });
```

The target's size comes from `player.extent`: a `radius`, or a box `size` with `hasSize` set.

**Lookahead**

```ts
camera.body = new PositionComposerBody(player, { lookaheadTime: 0.4, lookaheadIgnoreY: true });
```
